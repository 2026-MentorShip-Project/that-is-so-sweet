## Why

主揪投票時應沿用建立活動時的暱稱，避免重複輸入或被後端暱稱衝突規則拒絕。

## What Changes

- 手機版與桌面版傳入已判定的 isHost；主揪初次投票自動帶入 event.hostName 並固定暱稱欄位。
- 送出的 nickname 與固定顯示的主揪名稱一致，手機末三碼仍必填。
- 首次投票使用 optionalAuth，攜帶可用 JWT；匿名投票仍可用。更新投票沿用暱稱與手機末三碼驗證及 participant access token。
- 其他參與者仍可輸入暱稱，既有暱稱重複提示維持。

## Scenarios

- 主揪進入首次投票：顯示活動主揪名稱且不可編輯，手機末三碼仍空白；未輸入手機末三碼時不能送出。
- 主揪取消後再次進入、或由頁面直接進入 create 模式：仍自動帶入並固定主揪名稱。
- 其他參與者首次投票：暱稱欄位可編輯。
- 已登入使用者首次投票：POST 帶入 Bearer JWT；匿名使用者不帶 Authorization。
- 主揪已投票：沿用既有重複暱稱提示與更新投票流程。
